# Vehicle specs

Design: [vehicle-design.md](vehicle-design.md). Prefix `ING`, facets EP, VEH, ADM.

## Package and declaration (EP)

- [x] **ING-EP-001**: The distribution shall expose the frontend as one entry point named `riva_frontend` in the `vllm.endpoint_plugins` group, resolving to a zero-argument factory that returns `RivaFrontendPlugin`, and no Riva- or NIM-shaped code, dependency or route shall be merged into vLLM.
- [x] **ING-EP-002**: The distribution shall be named `vllm-riva-frontend` with import package `vllm_riva_frontend`, shall list among its runtime dependencies the pinned `nvidia-riva-client` stubs, `grpcio` with its health and reflection packages, `numpy`, `scipy` and `python-multipart`, and shall declare no dependency on vLLM or on the model plugin.
- [ ] **ING-EP-108**: The frontend's code shall import vLLM only inside the lifecycle methods (`attach_router`, `init_state`, `start`, `ready`, `drain` and `stop`), the path-scoped authentication middleware and the complete-file path (the frontend's file route and `Recognize`'s call to core's transcription service), and a check shall fail on a vLLM import anywhere else in the distribution.
- [ ] **ING-EP-062**: `RivaFrontendPlugin` shall have `name` equal to `riva_frontend` and `required_tasks` equal to `("realtime",)`, and shall require one API server process through `init_state` (ING-EP-081), not through a class declaration.
- [ ] **ING-EP-061**: When `riva_frontend` is loaded, one `vllm serve` API-server process shall serve, over exactly one engine client and one session factory: core's `/v1/realtime` and, for a model with the `transcription` task, core's `POST /v1/audio/transcriptions`, both unchanged and outside the frontend's ingress cap, file gate and guard; the frontend's route set under `/plugins/riva/v1/` (ING-SHIM-023) and its path-scoped authentication middleware, on the HTTP listener; and the Riva servicer, on one separate gRPC listener.
- [x] **ING-EP-020**: The frontend shall create no engine of its own and shall reach the engine only through the engine client core provides (the provider, loopback, render-loop and batching prohibitions are ING-CORE-018, ING-CORE-032 and ING-VEH-005).
- [x] **ING-EP-021**: The frontend shall add no vLLM version lower bound to its packaging and shall decide in `init_state` by capability (the session factory constructor raising on a missing engine call, and the `realtime` task) whether a vLLM build is usable.
- [x] **ING-VEH-002**: The gRPC vehicle shall register its servicer over the engine through the standard `add_RivaSpeechRecognitionServicer_to_server` call on an asyncio-native server and shall not commit one dedicated OS thread per concurrent streaming session for that session's duration.
- [x] **ING-VEH-005**: The frontend shall run no batching mechanism of its own; cross-session batching shall be provided entirely by the engine's own scheduler.
- [x] **ING-VEH-007**: Every downstream compatibility streaming adapter shall pass its validated cadence and locale only to `SessionFactory.open` and carry no per-session override through a process-shared serving object; Riva shall expose no mid-session configuration update, and after the Realtime adapter's first successful update and open only locale shall be mutable, applied through serialized `SessionLease.update_locale` before its truthful acknowledgement.
- [x] **ING-VEH-008**: Engine rendering and streaming-generation integration shall remain inside the model plugin's session and use the engine's process model configuration (SESS-PACK-*, SESS-ENG-*), and the frontend shall not render prompts or pass transport-owned configuration to the engine.
- [x] **ING-VEH-027**: Because the frontend is imported into the host's interpreter, the distribution shall declare the interpreter range derived from vLLM's `requires-python` (a narrower declaration is a defect) and remain installable and importable across it; every distributed module shall compile and import on the lowest supported version using no syntax or runtime name introduced later, except behind a version-gated import or a declared compatibility package; and that floor shall be proven by a gate that compiles and imports every module on that version, reports every offending module rather than halting at the first, and fails closed with an exit status no pipeline masks.
- [x] **ING-EP-022**: The linter target version and the type checker's language level shall name the lowest supported interpreter version, and the README's "Supported Python versions" table shall list every minor version in the declared range once, in order, as `supported` when a CI workflow's `python-version` matrix executes it and as `declared-but-unverified` otherwise, so that no unexecuted version is reported as supported.

## Startup checks (EP, VEH)

- [ ] **ING-EP-107**: When `init_state` runs, it shall fail startup unless the configuration is valid (ING-EP-018), the capacity checks hold (ING-EP-030 and ING-EP-029), and session-factory discovery and selection succeed as ING-CORE-012 and ING-CORE-017 state (exactly one accepting constructor, or the constructor that the `session_factory` option names).
- [ ] **ING-EP-068**: When `init_state` runs, it shall execute its checks in this order, raising one error that names every failed option within a step: configuration; served identity; engine stream deadlines; capacity; complete-file service; API server process count (ING-EP-081); authentication (ING-EP-086); the build of everything except the session factory (registry, ingress cap, file sub-cap, file gate, error catalog and the verifier the authentication middleware calls) followed by the route-table override check (ING-EP-070); and the session factory last.
- [ ] **ING-EP-069**: The plugin shall own every session factory a constructor returns during `init_state`: when discovery discards a factory (not the named one, or one of several accepting), it shall run the factory settlement (ING-EP-096) on that factory when it discards it, and if `init_state` fails after any factory was constructed, it shall run the factory settlement on every factory constructed and not yet settled before the error propagates, so that a failed `init_state` leaves no engine-facing task.
- [x] **ING-EP-025**: The `init_state` method shall bind no listener and start no task.
- [x] **ING-VEH-026**: During `init_state`, `riva_frontend` shall call `state.openai_serving_models.model_name()` exactly once and use its non-empty string result as the plugin lifetime's immutable served-model identity for every configuration, metadata and model-selector field of the Riva gRPC and Riva Realtime WebSocket surfaces and the operational routes; the frontend shall not read engine `ModelConfig`, `state.args` or a serve-argument namespace for identity, shall not parse CLI aliases, and a missing registry, a missing or non-callable accessor, a raised lookup, or a non-string or empty result shall fail `init_state` before the listener starts or any lease opens.
- [x] **ING-EP-026**: The Riva gRPC and Riva Realtime WebSocket surfaces shall accept only the primary served-model identity as a model selector, and the canonical checkpoint identifier and every secondary alias shall not be accepted as additional selectors there.
- [x] **ING-EP-027**: If `--shutdown-timeout` is 0, then `init_state` shall log a warning that no `drain` will run and that shutdown is `stop` alone.
- [x] **ING-EP-028**: When `init_state` finds data parallel size greater than 1, it shall fail startup.
- [ ] **ING-EP-081**: When `init_state` runs, it shall fail startup, naming the option, unless `args.api_server_count` counts exactly one API server process, where `None` or an absent attribute (core's single-process mode) and 1 count as one, and 0 (core's headless mode, which runs no API server) and any value above 1 fail, because every API server process would bind the gRPC port.
- [x] **ING-EP-029**: If the state-page count (`cache_config.num_gpu_blocks`) is `None` or 0, or the active-request limit cannot be read, then `init_state` shall fail startup.
- [x] **ING-EP-030**: The `init_state` method shall take the state-slot count as `vllm_config.cache_config.num_gpu_blocks - 1` and the active-request limit as `vllm_config.scheduler_config.max_num_active_seqs`, or `max_num_seqs` when that is unset.

## Engine deadlines (EP)

- [x] **ING-EP-013**: When `init_state` runs, it shall read `never_fed_timeout`, `parked_idle_timeout` and `draining_timeout` from `vllm_config.additional_config["stream_admission"]`, use 15 s, 60 s and 40 s respectively for an absent section or key, and fail startup for a present value that is not a finite positive number.
- [x] **ING-EP-014**: When `init_state` runs, it shall fail startup unless `first_audio_timeout` is below `never_fed_timeout`, `session_idle_timeout` and `lease_call_timeout` are each below `parked_idle_timeout`, and `session_finalization_timeout` is below `draining_timeout`.
- [x] **ING-EP-032**: The frontend's defaults for `first_audio_timeout`, `session_idle_timeout`, `lease_call_timeout` and `session_finalization_timeout` shall be 10 s, 45 s, 45 s and 30 s, so that the default deployment passes ING-EP-014.
- [ ] **ING-EP-071**: A test that runs in the RFC 1 + RFC 2 build, and only there, shall pin the frontend's copy of the three default stream deadlines (ING-EP-013) against core's stream-admission settings.
- [ ] **ING-EP-072**: Every frontend CPU test other than the stream-deadline pin of ING-EP-071 shall run against an RFC 2 build without RFC 1.

## Routes (EP)

- [ ] **ING-EP-063**: When core calls `attach_router`, the plugin shall add the frontend's route set (ING-SHIM-023), each route only after the collision check of ING-EP-091 and the frontend's file route only when core's `POST /v1/audio/transcriptions` is registered (ING-FILE-075), and shall add the path-scoped authentication middleware with `app.add_middleware`, so that it runs inside core's middleware (core's WebSocket metrics, authentication and CORS middleware wrap it); it shall add no route outside `/plugins/riva/v1/` and shall replace, shadow or wrap none of core's routes, including `/v1/realtime`, `POST /v1/audio/transcriptions` and `POST /v1/audio/translations`.
- [ ] **ING-EP-091**: When `attach_router` is about to add a frontend route, it shall first search `app.routes` and raise, stopping startup, when an existing HTTP route has the same path and method, an existing WebSocket route has the same path, or a mount's path is a prefix of the frontend route's path.
- [ ] **ING-EP-070**: When `init_state` has built everything except the session factory, it shall search the routes of the `app` kept from `attach_router` and fail startup unless, in core's final route table (after every plugin attached), the first route that matches each path the frontend added (and its method, for an HTTP route) is the frontend's own.
- [ ] **ING-EP-092**: A CPU test shall verify that, with the plugin loaded, core's route table equals core's table without the plugin plus exactly the frontend's routes: every core route keeps its path, methods, endpoint and relative order; every added route is under `/plugins/riva/v1/`; and the frontend's route set (ING-SHIM-023) collides with no route of core's table.

## Authentication (EP)

- [ ] **ING-EP-083**: The path-scoped authentication middleware shall apply its check only to a scope whose type is `http` or `websocket`, whose method is not `OPTIONS`, and whose path, after removing `root_path` as core does, starts with `/plugins/riva/`, and shall pass every other scope through unchanged, including the paths `/plugins/riva` and `/plugins/rivax` and every core path.
- [ ] **ING-EP-084**: While authentication is on (ING-EP-086), the path-scoped authentication middleware shall check the headers of each in-scope HTTP request and WebSocket handshake with the `verify_token` method of an instance of core's `AuthenticationMiddleware` that `init_state` builds with the resolved tokens, shall answer an HTTP request that fails the check with core's 401 response `{"error": "Unauthorized"}`, and shall pass a request that passes the check on to routing, so that an unknown path under `/plugins/riva/` is authenticated before routing answers it; while authentication is off, it shall pass every request through.
- [ ] **ING-EP-085**: When `init_state` decides whether an API key is configured, it shall apply core's selection rule: the candidate list is `args.api_key` when that list is non-empty and otherwise the single value of `VLLM_API_KEY`; empty strings are then discarded; and a key is configured when the result is non-empty, so that `--api-key ""` with a non-empty `VLLM_API_KEY` configures no key.
- [ ] **ING-EP-086**: When `init_state` decides authentication, it shall take as registrations the entries of the registered middleware list of the `app` kept from `attach_router` whose class is core's `AuthenticationMiddleware`, a registration being readable when it has a `tokens` keyword whose value is a non-empty list of non-empty strings; it shall turn authentication off when no key is configured (ING-EP-085) and no registration exists, turn it on with that registration's tokens when a key is configured and exactly one readable registration exists, and fail startup in every other combination with an error naming the signals it compared; and it shall never log the resolved tokens.
- [ ] **ING-EP-087**: If an in-scope WebSocket handshake fails the token check, then the path-scoped authentication middleware shall refuse it before `websocket.accept`: with core's 401 status and body through the ASGI WebSocket denial-response extension (`websocket.http.response`) when the scope's `extensions` include it, and otherwise by sending `websocket.close` before accept, which the ASGI server answers with HTTP 403 and no body; it shall never accept the connection.
- [ ] **ING-EP-088**: While authentication initialization is unresolved (`init_state` has not yet resolved the authentication tokens), the path-scoped authentication middleware shall fail closed: it shall answer an in-scope HTTP request with 503 and the body `{"error": "Service Unavailable"}`, and shall refuse an in-scope WebSocket handshake before `websocket.accept` as ING-EP-087 does, with a 503 status and that body through the ASGI WebSocket denial-response extension when the scope's `extensions` include it and otherwise by sending `websocket.close` before accept (HTTP 403); no catalog code applies (ING-ERR-061).
- [ ] **ING-EP-089**: Tests shall pin, against the core build, the core internals the path-scoped authentication middleware uses: the `AuthenticationMiddleware` class and its `verify_token` token check, the `tokens` keyword of that middleware's registration, and core's 401 body.
- [ ] **ING-EP-090**: The gRPC listener shall not apply `--api-key` or `VLLM_API_KEY`.

## Listener and readiness (EP)

- [x] **ING-EP-005**: When `start` runs, it shall create one `grpc.aio.server()` with the Riva servicer, the standard gRPC health service and server reflection registered, bind the configured address (refusing a port of 0) so that it is locally reachable before `start` returns, and keep gRPC health `NOT_SERVING` until admission opens.
- [ ] **ING-EP-080**: When `start` has started the fault collector and the listener monitor, it shall open admission as its last step and set gRPC health to `SERVING`, so that no owner is admitted before `start` completes, except that when core's `state.draining` is already set at that step it shall leave gRPC health `NOT_SERVING`.
- [ ] **ING-EP-064**: If `start` fails or is cancelled at any point, then it shall roll back what exists: cancel the fault collector and the listener monitor if it created them (so that the rollback's listener exit is not reported as a fault), stop the gRPC server without grace if it was bound, await the tasks it cancelled, run the factory settlement (ING-EP-096), and re-raise the failure or the cancellation; a cancellation that arrives during the rollback shall not interrupt it and shall be re-raised afterwards.
- [ ] **ING-EP-065**: The `ready(state)` method shall read attributes only and return true only while the gRPC listener is serving, neither core's `state.draining` nor the plugin's own drain flag is set, the plugin is not torn down, and no fault is recorded (ING-EP-017).
- [ ] **ING-EP-082**: The plugin shall count as draining from the moment core sets `state.draining`, before or without a `drain` call, as well as once its own `drain` has closed admission; its admission check (ING-ADM-018), file gate (ING-FILE-053) and `ready` (ING-EP-065) shall read `state.draining` directly; being draining shall establish no drain deadline `D`, which exists only while the frontend's `drain` call runs (ING-EP-066), so that without such a call every frontend bound holds unclipped until `stop` (ING-LIFE-062).

## Drain (EP)

- [ ] **ING-EP-066**: When `drain(state, timeout)` runs, the plugin shall compute core's deadline `now + timeout` and the graceful-work target `D = now + timeout - engine_reserve` with `engine_reserve` equal to `max(5 s, 10% of timeout)`, shall set gRPC health to `NOT_SERVING` and close admission, and shall bound every wait of graceful work inside `drain` (each lease call's bound and the factory wait included) by the time remaining to `D`; the settlement after the graceful work (ING-EP-093) shall take precedence over `D`.
- [x] **ING-EP-036**: While `drain` is running and its settle point `D - min(5 s, (D - now) / 4)` has not been reached, the plugin shall let owners finish normally.
- [ ] **ING-EP-109**: While `drain` is running with its graceful steps (ING-EP-075 not applying) and its settle point has not been reached, the plugin shall keep gRPC health `NOT_SERVING` and the gRPC listener serving, and shall neither raise the shutdown trigger nor begin stopping the listener, even when no owner remains, so that health checkers and load balancers observe `NOT_SERVING` before the listener closes; only `drain`'s cancellation or a failing step (ING-EP-076) shall end this interval earlier.
- [x] **ING-EP-037**: At the settle point the plugin shall raise the shutdown trigger carrying `D` for every remaining stream owner, and shall own only that trigger and `D` (ING-LIFE-053 and ING-LIFE-054 define the owner's sequence).
- [ ] **ING-EP-073**: At the settle point of `drain`, the plugin shall cancel every remaining file request (`Recognize` or the frontend's file route) so that it takes its cancellation path (ING-FILE-082), shall wait for each request's settlement no longer than the smaller of `session_cleanup_timeout` and the time remaining to `D`, and shall leave children still unsettled under their cleanup continuation (ING-FILE-079), with its permit and accounting, for the settlement (ING-EP-093) to await.
- [ ] **ING-EP-074**: When `drain` has completed its settle-point steps (ING-EP-037, ING-EP-073), it shall stop the gRPC server with the time remaining to `D` as the grace period, then end the fault collector (ING-EP-100), then call `factory.drain(D)` and log the faults it returns.
- [ ] **ING-EP-075**: If `drain`'s `timeout` is not larger than `engine_reserve`, then `drain`, after setting gRPC health to `NOT_SERVING` and closing admission (ING-EP-066), shall skip the graceful steps (the wait to the settle point, the shutdown trigger, the graceful listener stop and the graceful `factory.drain(D)`) and run the settlement (ING-EP-093) at once, aborting every owner by cancelling its task.
- [ ] **ING-EP-076**: If `drain` is cancelled, or one of its steps raises, then `drain` shall complete the settlement (ING-EP-093) without being interrupted by any number of further cancellations and only then re-raise: the cancellation when `drain` was cancelled, otherwise the step's exception.
- [ ] **ING-EP-102**: While core's `state.draining` is set and no `drain` call has run (no shutdown budget remains, as with core's default `--shutdown-timeout` of 0), admission shall refuse every new owner, `ready` shall be false, gRPC health shall stay as `start` left it, and no frontend bound shall be clipped to a drain deadline (ING-EP-082); when `stop` then runs, it shall stop the listener and settle everything that remains (ING-EP-079).

## Settlement (EP)

- [ ] **ING-EP-093**: When `drain` ends for any reason (after its graceful steps, when `D` or core's deadline passes, when a step raises, or when it is cancelled), and when `stop` runs, the plugin shall settle in this order before returning, raising or re-raising: abort every registered owner by cancelling its task; stop the gRPC server without grace if it is still serving; close the owner registry (ING-EP-106) to sends without an owner (ING-EP-095) and then await every owner task, every stream and file cleanup continuation with the children it holds, and every unsettled send in the registry until each has ended; end the fault collector (ING-EP-100) if it is still running; and run the factory settlement (ING-EP-096); every await shall be cooperative, with no fixed time limit.
- [ ] **ING-EP-095**: Each refusal send that creates no owner (an admission refusal's response or status, or a WebSocket query refusal's close before accept; not an engine-capacity refusal, which the refused stream's owner sends under its own record) shall be awaited inline by its own request handler under `response_send_timeout`; if the send is still unsettled one turn of the event loop after its bound passed and the registry is open, the handler shall cancel it and register it in the owner registry (ING-EP-106), from that moment, as a send without an owner that takes no ingress-cap count; if the registry is closed, the handler shall cancel the send and await it itself, keep awaiting it if the handler is cancelled, and re-raise that cancellation only once the send has ended.
- [ ] **ING-EP-094**: The settlement's close of the registry to sends without an owner, a refusal handler's check whether the registry is open, and that handler's registration of its abandoned send shall run on the event loop with no suspension between the check and the registration, so that every abandoned refusal send is either registered before the close or awaited by its own handler after it.
- [ ] **ING-EP-096**: When the plugin runs the factory settlement, it shall call `factory.drain(math.inf)`; then call `factory.teardown_all()`; then await every task `teardown_all` returned until each has ended, not stopping at a task that ends with an exception; record a last-resort fault, keyed by the task object, for each returned task that was not done when `teardown_all` returned; call `factory.drain(now)` once more; and report the faults both `factory.drain` calls returned, as returned, together with the last-resort faults.
- [ ] **ING-EP-097**: The plugin shall run the factory settlement (ING-EP-096) in `drain`'s settlement, in `stop`, in a rolled-back `start`, in a failed `init_state` and, within an `init_state` that continues, on each factory that discovery discards (ING-EP-069), in each case only after every owner, cleanup continuation and unsettled send has ended and the fault collector, if started, has ended; it shall log the faults the factory settlement reports, escalating none of them in `drain` or `stop`, and in a failed startup shall let the startup error propagate.
- [ ] **ING-EP-098**: In every settlement (`drain`, `stop`, a rolled-back `start`, a failed `init_state` and the settlement of a factory that discovery discards), the plugin shall itself deliver no cancellation directly to a factory task other than the last-resort cancellation that `teardown_all` applies to a task still running when it is called (ING-EP-096); a cancellation the plugin delivers to one of its own owners shall reach the factory only through the lease call that owner has outstanding, which the factory handles under its obligations (ING-CORE-027, ING-CORE-028).
- [ ] **ING-EP-099**: The plugin shall read no exception from the tasks `teardown_all` returns, shall report each fault `factory.drain` returns exactly as returned, and shall originate no fault for a factory task other than a last-resort cancellation, so that a `stop` after a completed `drain` settlement reports nothing that settlement already reported.
- [ ] **ING-EP-103**: A test in the model plugin repository's seam conformance suite, run on the RFC 1 + RFC 2 build with a real engine client (its GPU lane), shall establish that the real factory's `abort` and `release`, its retirement wait, and the engine client's abort of a cancelled `generate()` task end on an engine that core has stopped; and the frontend's RFC 2-only CPU lane shall cover the same settlement order (ING-EP-093, ING-EP-096) with the fake factory.

## Stop (EP)

- [ ] **ING-EP-079**: When `stop(state)` runs, it shall mark the plugin torn down (admission refuses and `ready` is false), run the settlement of ING-EP-093 with no graceful phase, every send bound counting as passed, and then cancel and await the listener monitor; a cancellation of `stop` shall not interrupt these steps and shall be re-raised afterwards.
- [ ] **ING-EP-077**: The `stop` method shall start no engine work of its own beyond its stream owners' `abort` and `release` (ING-LIFE-064) and the abort retries and final awaited `abort` that file cleanup continuations complete (ING-FILE-079), and shall await every task it cancels with no fixed time limit.

## Owners and faults (EP)

- [ ] **ING-EP-106**: The plugin shall register one owner per admitted gRPC stream, Realtime WebSocket session, `Recognize` call and request to the frontend's file route, each a task whose registry record persists until its last cleanup step, and a file request's cleanup continuation (ING-FILE-079) shall be registered with that record so that it outlives the handler after the route or RPC has answered; the plugin shall start no task outside the registry except the fault collector and the listener monitor, the two supervision tasks `start` creates, and refusal sends, each refusal send being awaited inline by its own request handler, which owns it until it registers the send on abandonment (ING-EP-095); and it shall leave every engine-facing task of a session to the factory.
- [ ] **ING-EP-067**: While serving, the fault collector (a frontend task that `start` creates) shall call `factory.drain` with an immediate deadline every second, serialized with every other `factory.drain` call of the plugin so that two callers never take the same faults, and record the retained faults it returns (the session leaf's ING-CORE-025 defines them).
- [ ] **ING-EP-100**: When `drain` or `stop` ends the fault collector, the plugin shall signal it to stop and await its end without cancelling it, so that a collection call in progress completes and its faults are recorded; a rolled-back `start` shall instead cancel and await it.
- [x] **ING-EP-016**: A frontend task shall watch the gRPC server's termination and treat an exit not caused by `drain` (including its settlement), `stop` or `start`'s own rollback (ING-EP-064) as a fault.
- [x] **ING-EP-017**: When any stream-path call fails with reason `engine_dead`, the fault collector records a fault, or the listener exits unexpectedly, the plugin shall record the fault so that `ready` is false and call `state.request_shutdown()`.
- [ ] **ING-EP-101**: The plugin shall not escalate for a refusal or failure surfaced to the owner that made the call (a refusal `open` raises with `session_error` `"refused"`, a lease failure reason other than `engine_dead`, or an exception raised with `session_error` `"failed"` and a reason other than `engine_dead`), and a test shall check that an ordinary capacity refusal and an ordinary generation failure produce no collected fault and no escalation.
- [x] **ING-EP-044**: When a session's cleanup bound expires, the plugin shall not treat that expiry as an escalation trigger.
- [x] **ING-EP-045**: The plugin shall not escalate for engine death on the file path, which core's own engine watchdog handles.

## Configuration (EP)

- [x] **ING-EP-018**: When `init_state` reads `additional_config["riva_frontend"]`, it shall fail startup for an unknown key, an explicit `null`, a non-finite or non-positive number, or an integer option given a non-integer, shall name the key `riva_frontend` and the offending option in the error, and shall report all failures together.
- [x] **ING-EP-046**: The plugin shall define no `plugin_shutdown_grace` option and shall take its shutdown budget from core's `--shutdown-timeout`.
- [x] **ING-EP-055**: When `grpc_keepalive_seconds` is set, `start` shall create the gRPC server with the keepalive ping interval set to that value (`grpc.keepalive_time_ms` equal to the value times 1000), and when it is unset shall set no keepalive option.
- [x] **ING-EP-047**: The plugin shall default the gRPC and listener options to `grpc_bind` `0.0.0.0:50051`, `grpc_receive_max_bytes` 33,619,968, `grpc_config_envelope_max_bytes` 65,536, `unary_max_encoded_audio_bytes` 33,554,432, `unary_max_decoded_duration_seconds` 600, `max_riff_header_bytes` 1,048,576 and `pre_submit_max_samples` 65,536, with `grpc_keepalive_seconds` and `max_session_duration` off unless set.
- [x] **ING-EP-048**: The plugin shall default the timeouts to `preconfiguration_timeout` 30 s, `session_cleanup_timeout` 30 s, `file_gate_wait_timeout` 30 s, `http_body_read_timeout` 120 s and `response_send_timeout` 60 s, and `file_execution_timeout` to `max(300 s, 2 * unary_max_decoded_duration_seconds)`.
- [x] **ING-EP-049**: The plugin shall default the WebSocket and HTTP limits to `ws_receive_max_bytes` 16,777,216, `ws_event_envelope_max_bytes` 8,388,608, `http_multipart_envelope_max_bytes` 33,816,576, `http_content_type_max_bytes` 4,096, `http_multipart_boundary_max_bytes` 200, `http_multipart_max_parts` 32, `http_multipart_max_header_bytes` 8,192 and `http_text_field_max_bytes` 4,096.
- [x] **ING-EP-050**: When `init_state` validates configuration, it shall fail startup unless the gRPC receive relation of ING-GRPC-031 and the WebSocket receive relation of ING-NIMWS-012 hold, `max_riff_header_bytes` is at most `unary_max_encoded_audio_bytes`, and `grpc_bind` is `host:port` with the port in 1 to 65535.
- [x] **ING-EP-051**: The plugin shall read its `session_factory` option as the entry-point name that selects one factory when several accept, defaulting to unset.
- [x] **ING-EP-052**: When `init_state` validates `deployment_image`, `pin`, `precision_policy` and `resampler_identifier`, it shall fail startup for a value with leading or trailing whitespace or containing `://`, and for a bare hexadecimal token of 8 to 64 characters in any of them except `pin`.

- [ ] **ING-ADM-018**: The frontend shall keep one finite positive ingress cap (`load_shed_max_sessions`, default 64) counting active owners across `StreamingRecognize`, `Recognize`, the Realtime WebSocket route `/plugins/riva/v1/realtime` and the frontend's file route `POST /plugins/riva/v1/audio/transcriptions`, excluding core's `/v1/realtime` and `POST /v1/audio/transcriptions`, `GetRivaSpeechRecognitionConfig`, the bootstrap POST, the operational routes, a WebSocket connection refused for its query, and every request the authentication middleware refuses; before reading the first message or request body (for `Recognize`, at servicer entry before any decode), parsing multipart, or calling `open`, a handler shall atomically check that the plugin is serving (core's `state.draining` unset, admission open and not torn down) and that the count is below the cap, and register its owner when both hold.
