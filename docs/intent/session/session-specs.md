# Session specs

Design: [session-design.md](session-design.md). Prefix `ING`, facets CORE, LIFE.

## Seam and ownership (CORE)

- [x] **ING-CORE-018**: Every streaming surface shall bind to the model only through the session factory and lease that the model plugin publishes, in process, and the frontend shall implement no remote provider, provider-mode configuration switch, generic session event broker, or internal WebSocket hop through `/v1/realtime`.
- [x] **ING-CORE-009**: Every streaming surface shall translate its dialect directly to and from `SessionFactory` and `SessionLease` calls and results without a second generic session event bus, shall own decode and resample, the bounded buffer between transport read and `feed`, read-side flow control, wire projection and the transport owner's lifecycle, and shall leave the packer, the engine binding and the consequences of a failed unit to the model plugin's session (SESS-PACK-001 to SESS-PACK-008, SESS-ENG-001 to SESS-ENG-009, SESS-LEASE-005).
- [ ] **ING-CORE-032**: Every streaming surface shall call `SessionFactory.open(*, cadence, locale)` and drive only the returned lease's `feed`, `update_locale`, `flush`, `finish`, `abort` and `release` operations, never calling its `teardown()`, shall use `feed`'s `on_accepted` callback for exact outstanding-sample credit release, and shall implement no engine generation or render loop, cadence arithmetic, dedicated batcher or internal WebSocket loopback.
- [x] **ING-CORE-012**: When `init_state` discovers session factories, it shall call each constructor in entry-point group `vllm_riva_frontend.session_factories` with `(engine_client, engine_client.model_config)` unchanged, treat a constructor that returns `None` as not serving the model, and fail startup if a constructor raises.
- [x] **ING-CORE-017**: When `init_state` finds that zero or more than one constructor returns a factory and `additional_config.riva_frontend.session_factory` is unset, it shall fail startup listing the entry-point names; when that option names an entry point, `init_state` shall use only that constructor's result and fail startup if it is absent or declines.
- [ ] **ING-CORE-033**: The frontend shall import no model-plugin package, shall use the factory (`served_cadences`, `locales`, `default_locale`, `open`, `drain`, `teardown_all`) and the lease (`feed`, `update_locale` returning `None`, `flush`, `finish`, `abort`, `release`) only through their structural protocol, and shall read `session_error` and `reason` from an exception with `getattr` without catching a model-plugin exception class by name.
- [x] **ING-CORE-014**: Every streaming surface shall open its session at cadence `560ms`, and `init_state` shall fail startup if the factory's `served_cadences` does not contain `560ms`.
- [x] **ING-CORE-015**: A stream's locale shall be the client's locale validated against the factory's `locales`; when the client names none the locale shall be `default_locale`; and when that is `None` and the client names none, the surface shall answer `invalid_config_field` naming the dialect's locale field (`language_code` for Riva).
- [ ] **ING-CORE-022**: The repository shall ship a seam conformance suite, run against a fake factory that models cleanup and holding tasks outliving the owner that handed their session over, and run against the model plugin's real factory in the model plugin repository's seam conformance run on the RFC 1 + RFC 2 build, that checks: `drain` with an absolute deadline awaiting cleanup tasks and returning the recorded faults once, clearing them (SESS-OWN-004); the first `teardown_all` call closing the factory and cancelling and returning every task it owns, including the generation task of a session whose `abort` was cancelled and the cleanup task of a session whose `release` was cancelled (SESS-OWN-005); a closed factory refusing `open` and every lease call other than `teardown` (SESS-OWN-006); a `release` after a cancelled `abort` keeping a tracked task until the generation task ends (SESS-ABORT-002); a cancelled `release` leaving the session with the factory's cleanup (SESS-REL-003, SESS-OWN-003); the call order the owner relies on; the error attributes, including a reason the frontend does not know; and each factory obligation ING-CORE-023 to ING-CORE-029 and ING-CORE-034, with the tests of ING-CORE-030.
- [ ] **ING-CORE-031**: A session factory constructor shall start no task or session, so that a factory is inert until its first `open`, and a test in the model plugin repository's seam conformance run, on the RFC 1 + RFC 2 build, shall verify this against the model plugin's factory constructor.
- [x] **ING-CORE-019**: Each cumulative transcript string that `SessionLease.feed` returns (SESS-IN-004) shall be projected so that Riva gRPC emits a changed cumulative hypothesis as a non-final `StreamingRecognizeResponse` only when `interim_results` is true, the Realtime adapter emits the true incremental suffix between consecutive cumulative hypotheses, and a `feed` that returns no transcript emits no wire result.
- [x] **ING-CORE-021**: Each streaming handler shall read exactly its first configuration message, validate either a concrete accepted audio cell or the dialect's explicit deferred-RIFF declaration, complete `open`, and only then advance the gRPC request iterator or receive a WebSocket event other than a configuration retry, where after a rejected initial configuration the Realtime handler shall receive further `transcription_session.update` events within the original `preconfiguration_timeout` (not reset by a retry), admit no audio before `open` succeeds, and treat any other event as the wrong-first-message case of ING-LIFE-001; pipelined pre-open audio shall remain under transport flow control rather than enter a frontend buffer; in deferred-RIFF mode the handler shall hold at most `max_riff_header_bytes` after `open` and call no `feed` until the concrete cell resolves; and while a `feed` call is awaiting the engine and the handler cannot hand over more audio, the handler shall stop reading that transport within the `pre_submit_max_samples` bound, except for the receive observer of accepted client-selected finalization (ING-ERR-057), which reads during the final-tail `feed` and `flush`.
- [x] **ING-CORE-011**: When `open` returns a lease after complete initial-configuration validation, the owner shall enter the internal `configured` state before the transport is consumed, the Riva servicer shall emit no invented configuration or admission acknowledgement, and the Realtime adapter's `transcription_session.updated` shall acknowledge the validated configuration and add no admission vocabulary.

## Factory obligations (CORE)

The frontend imposes these on every session factory it uses (Factory obligations 1 to 8 of the session design); each is owed as a statement in the model plugin's session specification, and ING-CORE-025 and ING-CORE-026 also need a change to the model plugin's code. Each stays `[ ]` until the seam conformance suite's test of it (ING-CORE-022) passes against the fake factory in the frontend's CPU lane and against the real factory in the model plugin repository's conformance run, and, for ING-CORE-025 and ING-CORE-026, until that code change has landed.

- [ ] **ING-CORE-023**: A session factory the frontend uses shall accept `math.inf` as `drain`'s deadline; a `drain` call given `math.inf` before `teardown_all` has been called shall return only when every cleanup task and every holding task (a task that holds a session after a failed retirement wait) that exists when `drain` is called has ended, cancelling no task by the wait; a `drain` call given a finite deadline, such as the current time or the drain deadline `D`, shall wait for those tasks only until they end or the deadline passes, whichever is first, cancelling none (SESS-OWN-004); and a `drain` call after `teardown_all` follows ING-CORE-034.
- [ ] **ING-CORE-024**: A session factory the frontend uses shall end each of its cleanup and holding tasks only after that session's generation task has ended, except a cleanup or holding task that `teardown_all` cancels, and neither kind of task shall cancel the generation task; `teardown_all` shall still return every task it cancels, cleanup and holding tasks included, for the caller to await.
- [ ] **ING-CORE-025**: A session factory the frontend uses shall retain, and return through `drain`'s fault list even after their session is dropped, exactly these faults, each an exception other than `CancelledError`: an exception of a cleanup task's retirement wait that reports a dead engine or is unexpected; an exception of a generation task that no `open` or lease call surfaced to its caller, because the task ended after its session was handed over to a cleanup or holding task or because its cancellation handler raised while an uncancelled `abort` awaited it (that `abort` then returning normally); and an exception of a cleanup or holding task itself; it shall not retain a refusal `open` raises with `session_error` `"refused"`, a generation failure projected as a lease `reason` (`engine_dead` among them) or raised with `session_error` `"failed"`, or the cancellation of a task that `teardown_all` cancels as a last resort.
- [ ] **ING-CORE-026**: A session factory the frontend uses shall be the only reporter of its tasks' faults, returning each retained fault (ING-CORE-025) through `drain` exactly once and clearing it, so that a fault returned to one caller is never returned to another.
- [ ] **ING-CORE-027**: A session factory the frontend uses shall ensure that its `open`, `abort` and `release` and its own cleanup and holding tasks deliver no cancellation to a generation task after that task's cancellation handler has begun; `teardown_all` and the lease's `teardown()` are excepted, since they cancel unconditionally by contract (SESS-OWN-005, SESS-TEAR-001).
- [ ] **ING-CORE-028**: A session factory the frontend uses shall ensure that its `release` does not suspend before its cancellation-safe hand-over coverage is in place, so that a cancellation delivered at any suspension after the call has started hands the session over to the factory's cleanup (extending SESS-REL-003, which covers a cancellation before the retirement wait finishes, to every suspension).
- [ ] **ING-CORE-029**: A session factory the frontend uses shall start no task after `teardown_all` has been called.
- [ ] **ING-CORE-034**: A session factory the frontend uses shall, once `teardown_all` has been called and every task it returned has ended, return from every later `drain` call at once, whatever its deadline, with only the retained faults it has not yet returned (ING-CORE-026), and shall return no task still running and raise no exception from every later `teardown_all` call, so that a `stop` after a completed `drain` settlement completes its factory settlement (ING-EP-096) at once.
- [ ] **ING-CORE-030**: The seam conformance suite (ING-CORE-022) shall include tests that: an ordinary capacity refusal (`open` raising `SessionRefused`) and an ordinary generation failure seen by the owner as a lease reason leave `drain`'s fault list empty; a generation task whose cancellation handler raises while it awaits the engine abort, after its session was handed over, yields exactly one fault, returned by a later `drain` after the cleanup task has ended and dropped the session and by no later `drain`; a generation task whose cancellation handler raises while an uncancelled `abort` awaits it lets that `abort` return normally and yields exactly one fault, returned by one later `drain` and by no other; a cancelled `open`, which requests cancellation twice with no suspension between the requests, after its generation task has started, delivers no cancellation to the generation task after its cancellation handler has begun, leaves the session covered by a holding or cleanup task, and leaves no factory task running after the vehicle's factory settlement; a cancelled `open` whose generation task is cancelled before its first step leaves that task never running its body, making no engine call, and ending within one turn of the event loop; and the release hand-over, run through the owner's own cancellation mechanism (ING-LIFE-060), leaves the session with the factory's cleanup, against the fake factory in the frontend's RFC 2-only CPU lane and against the real factory in the model plugin repository's seam conformance run on the RFC 1 + RFC 2 build.

## Owner and finalization (LIFE)

- [x] **ING-LIFE-001**: The first client message on every downstream compatibility streaming surface shall be that dialect's session configuration; when any other message arrives first, Riva shall answer `protocol_order` with gRPC `FAILED_PRECONDITION` and the Realtime adapter shall send `error` then close.
- [x] **ING-LIFE-002**: A Riva streaming session shall map client half-close to one finalization and a Realtime session shall map `input_audio_buffer.done` to one finalization, each emitting exactly one dialect final only after normal finish and release succeed and then closing, with no multi-utterance reuse.
- [x] **ING-LIFE-003**: When either streaming surface finalizes with zero total audio, the owner shall call `flush` (SESS-FLUSH-001), then `finish` and `release` normally, before emitting exactly one empty dialect final.
- [x] **ING-LIFE-024**: When finalization is accepted while a deferred RIFF header is unresolved, the owner shall treat zero received bytes as a zero-audio stream with a valid empty final and shall end a partial header with `unsupported_format` naming the fields, `abort` and `release`, and no final.
- [x] **ING-LIFE-017**: When a streaming surface finalizes normally, the owner shall first feed the audio frontend's drained tail (ING-FE-010) under the finalization bound, then call `flush` unconditionally (including with zero audio) and take the final transcript from its return value, treating any non-string return as a failed `flush`; this derivation shall occur at exactly one point shared by every streaming surface.
- [x] **ING-LIFE-025**: After a successful `flush`, unless an abnormal cause has been selected (ING-LIFE-026), the owner shall call `finish` exactly once and then `release`, and the surface shall expose the dialect final only after both succeed.
- [x] **ING-LIFE-026**: If `flush` fails, or a cancellation, deadline, disconnect, idle timeout or abort during shutdown wins before normal completion, then the owner shall use only the calls the lease's state allows (SESS-LEASE-001): from an open or failed lease, `abort` and then `release` and never `finish`; from a flushed lease, `release` only (ING-LIFE-027); and `release` shall not precede the selected terminal cleanup.
- [x] **ING-LIFE-027**: The owner shall never call `abort` on a lease that has already been flushed, and when `finish` fails or is cancelled after a successful `flush` it shall proceed to `release` only.
- [x] **ING-LIFE-028**: If `finish` settles successfully, then the normal engine terminal shall stand, cleanup shall proceed only to `release`, and a later transport failure shall suppress the wire final without turning the stream into an abort.
- [x] **ING-LIFE-007**: When a configured Realtime session receives a later update changing locale, its owner shall validate and serialize `SessionLease.update_locale`, answer an unknown locale with `unknown_locale` and preserve the prior selection, acknowledge a valid locale only after the call succeeds, the new locale applying from the next unit the model packs (SESS-LOC-001, SESS-LOC-002), and after accepted finalization freeze the current locale and reject every later update.
- [x] **ING-LIFE-008**: After a Realtime session's first successful update and open, every changed cadence, audio-format, sample-rate, channel or recognition-option field shall answer `config_change_rejected` and leave the active lease and front end unchanged even when no audio has arrived, and a later Riva `streaming_config` shall instead answer terminal `protocol_order`.
- [x] **ING-LIFE-009**: When a configured Realtime session receives a later update before accepted finalization, the adapter shall emit any field rejection events first and then exactly one `transcription_session.updated`, last, reflecting exactly the honoured subset (an honoured locale change, or the unchanged session when nothing is honoured), truthful and with no admission claim.

## Shutdown finalization (LIFE)

- [x] **ING-LIFE-053**: A stream owner shall select provisional shutdown mode at the instant it observes the shutdown trigger, before it settles any outstanding lease call, unless a client-selected finalization is already running (ING-LIFE-055) or an abnormal cause was already selected, which is kept; provisional shutdown mode shall not be an immutable cause, so that any failure or deadline expiry after the trigger is observed, including during the settlement of the outstanding call, shall end the stream with the shutdown abort row (ING-ERR-062) because the session is being shut down; and every deadline the owner already holds shall keep its original value and identity, its waits being clipped to `D` (ING-ERR-056).
- [x] **ING-LIFE-054**: When the vehicle raises the shutdown trigger with deadline `D`, a stream owner holding an open lease and not yet finalizing shall select provisional shutdown mode (ING-LIFE-053), wake from a pending transport receive by cancelling that receive and not a lease call, settle any outstanding lease call under that call's own deadline with the wait clipped to `D`, enter `finalizing` for shutdown finalization, and run the finalization sequence of ING-LIFE-017 and ING-LIFE-025 under its finalization bound clipped to the time remaining to `D` (ING-LIFE-062).
- [ ] **ING-LIFE-065**: When a stream owner enters shutdown finalization (ING-LIFE-054) holding an already-read, validated audio message whose slices it has not all handed to `feed` (ING-FE-011, ING-GRPC-019, ING-NIMWS-018), it shall feed the remaining slices of that message, each `feed` under its operation bound with the wait clipped to `D` (ING-LIFE-062, ING-EP-110), before it drains the resampler (ING-FE-010) and calls `flush`, and shall read no further transport message (ING-LIFE-034); if it cannot complete those slices, the cause shall become an abort during shutdown with the shutdown abort row (ING-LIFE-048, ING-ERR-062), and no successful final shall be delivered.
- [x] **ING-LIFE-029**: When the shutdown finalization sequence succeeds, the surface shall deliver the final only after `release` succeeded and then end the stream as ING-ERR-027 defines.
- [x] **ING-LIFE-048**: If the shutdown finalization sequence fails, its finalization bound expires, or `D` arrives first, then the cause shall become an abort during shutdown, an open or broken lease shall take `abort` then `release`, a flushed lease shall take `release` only, and the stream shall end with the shutdown abort row (ING-ERR-062).
- [x] **ING-LIFE-031**: When the shutdown trigger finds an owner with no lease that is waiting for configuration or first audio, the owner shall end the stream with the shutdown code without finalizing.
- [x] **ING-LIFE-032**: When the shutdown trigger finds an owner with `open` pending, the owner shall let `open` complete or cancel it under the cancelled-`open` rule and then treat the result as no lease or as an open lease.
- [x] **ING-LIFE-055**: When the shutdown trigger finds an owner already in client-selected finalization, the owner shall cancel its receive observer (ING-ERR-057, ING-LIFE-034), continue from its current step, shall not re-feed the tail or re-`flush`, and shall keep that finalization's own deadlines (waits clipped to `D`) and codes (ING-ERR-048, ING-ERR-023, ING-ERR-024) unchanged, except that a wait ending because it reached `D` before its own deadline shall end it with the shutdown abort row (ING-ERR-062); a finalization that succeeds shall keep its own outcome, delivering its final and ending as a client-selected finalization ends (gRPC `OK`; Realtime close 1000, ING-NIMWS-023); and when the trigger finds abnormal cleanup already selected, the owner shall continue that cleanup with the selected cause unchanged.
- [x] **ING-LIFE-034**: After the shutdown trigger the owner shall read no further transport message, shall not classify unread traffic, and shall reserve `session_terminal` for client-selected finalization.

## Terminal cause and cleanup (LIFE)

- [ ] **ING-LIFE-063**: Each streaming session that passes the ingress cap (ING-ADM-018) shall register exactly one owner, a task whose registry record persists until the stream's handler, its cleanup continuation and every unsettled send of the stream have ended, before reading its first message, and keep it tracked until `SessionLease.release` returns or the session has passed to the factory through an awaited cancelled `release` (ING-LIFE-060) or a cancelled `open` (ING-LIFE-036) (file-request owners: ING-EP-106 and ING-FILE-079); and a stream owner shall serialize every lease call and atomically select exactly one terminal cause; the stream's ingress-cap count shall be released exactly once, when the owner and its cleanup continuation have ended, and a registry record that persists after that only for the stream's unsettled sends shall take no ingress-cap count (a file owner's count follows ING-ADM-016).
- [x] **ING-LIFE-056**: One serialized stream owner shall atomically record exactly one winning terminal cause at an owner-operation boundary, where a transport cancellation or an expired deadline already observed before the next boundary wins, the deadline rule (ING-ERR-056) choosing among expired deadlines, and otherwise an already-computed validation or protocol result or the first timer, shutdown, factory, input or engine cause recorded there stays primary; a provisional normal or shutdown finalization shall not be such a cause and shall yield to a later abnormal cause or deadline (ING-LIFE-053), while an abnormal cause once recorded shall be immutable; and later transport or cleanup failures shall not replace the primary catalog code.
- [x] **ING-LIFE-035**: After selecting an abnormal cause, the owner shall cancel and await bounded settlement of its current `open`, `feed`, `update_locale`, `flush` or `finish` and only then run terminal cleanup shielded from further cancellation, and two lease calls shall never overlap.
- [x] **ING-LIFE-036**: When a cause is selected while `open` is pending, the owner shall cancel `open`, shall call neither `abort` nor `release` for a lease it never received, and shall leave the session to the factory (SESS-OPEN-006).
- [ ] **ING-LIFE-059**: A stream owner's terminal cleanup shall run under one bound, shared by its calls, fixed when terminal cleanup begins (including the settlement of a cancelled call) and neither extended nor restarted afterwards, including when the drain deadline `D` passes or the vehicle's settlement cancels the owner (ING-EP-110): when cleanup begins while a frontend `drain` call is running its graceful work (`D` not passed and its settlement, ING-EP-093, not begun), the bound shall be the time remaining to `D`, which replaces `session_cleanup_timeout` and is not capped by it (a file owner's cleanup takes the smaller of the two, ING-FILE-078); when cleanup begins at any other time, including while core's `state.draining` is set and no `drain` call has run (ING-EP-082, ING-EP-102), after `D`, in the vehicle's settlement (also when `drain` fails or is cancelled) and in `stop`, the bound shall be `session_cleanup_timeout` from that start.
- [ ] **ING-LIFE-060**: When a stream owner's cleanup bound expires, before or after the drain deadline, the owner shall cancel an outstanding `release`, or cancel an outstanding `abort`, await that call's settlement and then begin `release` and cancel it; the owner shall run `release` as a task, let it reach its first suspension and never cancel it before its first step, and shall await the cancelled `release` before the owner or its continuation counts as ended, so that the session passes to one tracked factory cleanup task (SESS-REL-003, ING-CORE-028) registered before the vehicle's factory settlement begins.
- [x] **ING-LIFE-020**: If a primary cancellation, deadline, validation, transport or engine error is selected, then a later cleanup error shall be recorded without replacing the primary wire result; on an otherwise normal path a `finish` failure, a `release` failure or a cleanup-bound expiry shall emit no final and shall not claim the resource was released; and a cleanup failure whose reason is `engine_dead` shall be reported as a fault (ING-EP-111).
- [x] **ING-LIFE-038**: When a transport-level disconnect is detected (WebSocket disconnect, TCP FIN or RST, gRPC stream cancellation; listener stop: ING-LIFE-064), the owner shall immediately select abnormal termination and run shielded bounded cleanup (`abort` then `release`, or `release` only for a flushed lease), and the session shall never be left to the engine's idle deadlines.
- [x] **ING-LIFE-039**: When a gRPC stream is cancelled during a lease call, the servicer shall observe the cancellation immediately through the context's done callback, and when a WebSocket disconnects during an outstanding lease call the adapter shall observe it when that call returns or its per-operation bound expires, whichever is first.
- [ ] **ING-LIFE-064**: When the vehicle's settlement (ING-EP-093) cancels a stream owner, in `drain` or in `stop` while the plugin is torn down, or the servicer observes the termination of an RPC after the plugin began stopping the gRPC listener (the graceful stop of ING-EP-074 or the forced stop of ING-EP-093), which shall count as the plugin's cancellation of the owner and never as a client disconnect (ING-LIFE-038, ING-LIFE-039), the owner shall keep a cause it already selected and otherwise take the shutdown abort row (ING-ERR-062), cleaning up by lease state (an open or failed lease `abort` then `release`, a flushed lease `release` only, a pending `open` cancelled with no lease call) under the bound of ING-LIFE-059, calling no `teardown()` (ING-CORE-032); and a test of a listener stop shall assert the selected cause and the cleanup, not the status the client receives.

## Bounds (LIFE)

- [ ] **ING-LIFE-062**: On a streaming surface, every lease call and every wait for client input shall run under a finite frontend bound (configuration, first audio, idle, per-operation, finalization, cleanup); while a frontend `drain` call is running its graceful work (its drain deadline `D` not passed and its settlement, ING-EP-093, not begun, ING-EP-110), each wait of graceful work shall be clipped to the time remaining to `D` when that is smaller, the bound keeping its own absolute deadline and identity (ING-ERR-056); while the plugin is draining with no `drain` call (ING-EP-102), every bound shall hold unclipped until `stop`; and a stream owner's terminal cleanup shall not be clipped but shall take the bound of ING-LIFE-059 instead, which is the time remaining to `D` in place of `session_cleanup_timeout` when that cleanup begins during graceful work, and `session_cleanup_timeout` when it begins in the vehicle's settlement.
- [ ] **ING-LIFE-061**: On every streaming surface, every send and close (hypotheses, acknowledgements, errors, the final, and the refusals of ING-ERR-015, ING-NIMWS-027 and ING-NIMWS-028 that create no owner) shall be bounded by `response_send_timeout`, clipped to the gRPC RPC's absolute deadline and, while a frontend `drain` call is running its graceful work (ING-LIFE-062), to `D`, that `drain` call announcing `D` to every send in flight so that a waiting send re-clips at once (while the plugin is draining with no `drain` call, ING-EP-102, the bound is not clipped); a send or close that exceeds the bound shall end an owner by the transport-failure path, with no further sends and cleanup as for a disconnect (ING-LIFE-038), the handler cancelling the send without waiting for it and a send still unsettled after one turn of the event loop staying under the stream's record until it settles or the vehicle's settlement awaits it, while a refusal that created no owner shall follow ING-EP-095; a send whose bound has already passed shall not start unless it carries a terminal status (a gRPC status or abort; a Realtime `error` event, or the `conversation.item.input_audio_transcription.failed` event that ends the session, and its close, sent in sequence as one attempt (ING-EP-110); for a refusal that creates no owner, its whole sequence as ING-EP-110 defines it, the `websocket.accept` of ING-NIMWS-028 included), which shall get one attempt that adds no wait and is cancelled if not complete at its first suspension; a send that has not completed when its bound passes shall count as failed even if it completes later; and every send bound shall count as passed after the plugin is torn down and, for the rest of a `drain` call, once its drain deadline `D` has passed, its settlement has begun or it skips its graceful steps (ING-EP-110); once a send's failure is established (its bound observed as passed, or a terminal attempt found incomplete at its first suspension), a later cancellation of the handler shall not change that disposition and no further send shall be made, while a send interrupted by the plugin's cancellation of its owner (the vehicle's settlement of a drain, or `stop`) before its failure is established shall not take the transport-failure path and the owner shall take the shutdown abort row, whose terminal status is sent under its bound, or gets the one attempt once that bound has passed; a terminal status or close that is itself so interrupted shall end the stream with no further send.
- [x] **ING-LIFE-040**: From successful `open` until the first accepted audio the owner shall apply `first_audio_timeout`, and from the first accepted audio shall apply `session_idle_timeout`, reset by each successful application-level audio acceptance and not by socket bytes, keepalive or rejected overflow.
- [x] **ING-LIFE-041**: While a lease call is outstanding, the owner shall suspend `first_audio_timeout` and `session_idle_timeout` and resume them when the call returns.
- [x] **ING-LIFE-042**: When a `feed` or `update_locale` call exceeds `lease_call_timeout`, the owner shall cancel the call, treat the lease as broken, take `abort` then `release`, and project the code of the errors leaf's phase table.
- [x] **ING-LIFE-052**: When the first-audio or idle bound expires, the owner shall call `abort` exactly once and then `release`, and the frontend shall surface `idle_timeout` in the session's dialect before closing.
- [x] **ING-LIFE-043**: While `max_session_duration` is set, the owner shall measure it from successful `open` without reset, and its expiry before accepted finalization shall abort and release and project `request_timeout`.
- [x] **ING-LIFE-044**: When finalization is accepted, the owner shall atomically disarm the first-audio, idle and duration bounds and apply the finalization and cleanup bounds.
- [x] **ING-LIFE-021**: When a lease fails with reason `expired`, the surface shall project `idle_timeout` (SESS-EXP-001 defines the reason).
- [x] **ING-LIFE-022**: When a Riva streaming RPC or an admitted Realtime WebSocket connection is registered as an owner, a finite `preconfiguration_timeout` shall begin and end only after the complete initial configuration validates and `open` succeeds, its expiry shall project `configuration_timeout`, release the owner slot and cancel a pending `open` without calling `abort` or `release` for a lease it never received, and it shall stay distinct from `idle_timeout`.
- [x] **ING-LIFE-045**: The Realtime bootstrap POST shall create no owner and start no timer.
