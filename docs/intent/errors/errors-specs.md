# Error catalog specs

Design: [errors-design.md](errors-design.md). Prefix `ING`, facet ERR.

## Catalog and projection (ERR)

- [ ] **ING-ERR-042**: Every error the frontend surfaces on a compatibility dialect shall carry a stable code string from the frontend's error catalog and use that dialect's catalog projection, on gRPC the code leading the status details and for the Realtime WebSocket transcription failures using `conversation.item.input_audio_transcription.failed` and protocol or session failures using `error`, and no failure, rejection or deviation shall be silent; the exceptions are gRPC's native rejection of a message above the framework cap (ING-GRPC-031) and core's own errors on the file route, which pass through unchanged (ING-ERR-009).
- [ ] **ING-ERR-029**: Every gRPC error the servicer raises shall be raised through `context.abort` with status details of the form `<code>: <detail> (fields: <names>)`, the framework's native rejection of a message above `grpc_receive_max_bytes` (ING-GRPC-031) being the one gRPC error the servicer does not raise.
- [ ] **ING-ERR-051**: A Realtime `error` event shall carry the code and the field names, and `authority` for `busy`, and where the catalog requires a close the adapter shall send every pending event before closing while the transport accepts each send within the send bound of ING-LIFE-051 (a terminal `error` event and close due after the bound get the one attempt ING-LIFE-051 allows), and once a send exceeds that bound shall abandon the connection with no further send, including the close frame.
- [ ] **ING-ERR-043**: `busy`, `admission_wait_timeout`, `idle_timeout` and `finalization_timeout` shall be distinct catalog codes, no surface shall conflate capacity or load shedding, a bounded admission wait, inactivity, and accepted finalization that reached its bound, and `admission_wait_timeout` shall be reserved and emitted by no surface.
- [ ] **ING-ERR-003**: Every rejection of a config field, format or capability shall name the offending field or fields in the error payload.
- [ ] **ING-ERR-057**: After a streaming surface accepts client-selected finalization (`input_audio_buffer.done` on the Realtime adapter, the half-close on gRPC), the owner shall keep reading the transport with a receive observer, bounded by the finalization bound and holding at most one received message, from acceptance (including during the final-tail `feed` and `flush`, an exception to ING-CORE-021's no-read rule) until the final's send begins or the owner observes the shutdown trigger, which cancels the observer; on the Realtime adapter a malformed or unknown envelope it sees shall keep `invalid_event` and close 1008 (ING-NIMWS-023), a message above the receive cap shall keep `request_too_large` and close 1009, and every other client message (`input_audio_buffer.append`, `clear`, `commit` or `done`, or `transcription_session.update`) shall fail the session with `session_terminal`; each of these three dispositions shall run under the state-aware cleanup of ING-LIFE-026, suppress the final whose send has not begun and make no lease call when it fires after `release`; once the final's send has begun the final shall be irrevocable and the owner shall read no further traffic; and no surface shall inherit core's silent second-commit behaviour.
- [ ] **ING-ERR-005**: An unexpected engine, session-factory, plugin, transport or terminal-cleanup failure with no more specific primary catalog error shall project `internal`, and a cleanup failure shall never replace an already-selected cancellation, deadline, validation, transport or engine error.
- [ ] **ING-ERR-046**: `service_unavailable`, `configuration_timeout`, `request_timeout`, `malformed_request` and `request_too_large` shall be distinct catalog codes meaning respectively that the plugin is starting, draining or not ready; that initial configuration plus `open` exceeded `preconfiguration_timeout`; that a streaming session exceeded `max_session_duration`, a file request exceeded its body-read, execution or response-send bound, or a gRPC absolute deadline won under the deadline precedence rule (ING-ERR-056); that the file route's multipart content type, boundary, structure, required file or framing is invalid; and that a bounded unary, audio-duration, WebSocket-envelope or file-route body resource exceeded its limit.
- [ ] **ING-ERR-031**: The catalog shall project the 20 codes to gRPC statuses `service_unavailable` `UNAVAILABLE`, `busy` and `request_too_large` and `buffer_overflow` `RESOURCE_EXHAUSTED`, `idle_timeout` `ABORTED`, `finalization_timeout` and `configuration_timeout` and `request_timeout` `DEADLINE_EXCEEDED`, `malformed_request` and `invalid_event` and `invalid_config_field` and `unknown_locale` and `unsupported_format` and `invalid_audio` `INVALID_ARGUMENT`, `session_terminal` and `protocol_order` `FAILED_PRECONDITION`, `unsupported_capability` `UNIMPLEMENTED`, `internal` `INTERNAL`, `config_change_rejected` `OK` (never raised as an abort) and `admission_wait_timeout` `DEADLINE_EXCEEDED`.
- [ ] **ING-ERR-055**: The file route shall project catalog codes to HTTP statuses `malformed_request` 400, `invalid_config_field` 400, `unknown_locale` 400, `request_too_large` 413, `request_timeout` 408 for a body-read timeout and 504 for a core-execution timeout before response headers are sent (after them the event stream is terminated, ING-FILE-035), `service_unavailable` 503, `busy` 503, `unsupported_capability` 501 (files disabled only) and `internal` 500, and a response-send timeout shall end delivery with no further send.
- [ ] **ING-ERR-033**: The Realtime adapter shall project `invalid_config_field`, `unsupported_capability`, `unknown_locale` and `config_change_rejected` as an `error` that leaves the session continuing when no state changed.
- [ ] **ING-ERR-034**: A format or configuration rejection before the first Realtime configuration completes shall not close the connection, so that the client can retry with a corrected `transcription_session.update`.

## Phase-specific mapping (ERR)

- [ ] **ING-ERR-011**: The phase table of the errors design shall govern the code, gRPC status, Realtime event and close of every streaming-session phase, and where another leaf states one of those values the phase table shall govern on any conflict.
- [ ] **ING-ERR-056**: Every deadline an owner holds (a phase bound, the gRPC RPC's absolute deadline, the drain deadline `D`) shall keep its original absolute value and its identity, and clipping (ING-LIFE-057) shall shorten only the wait, so that a wait that ends because it reached `D` shall expire as `D` and not as its phase; the earliest expired deadline shall win; a phase's code (`configuration_timeout`, `idle_timeout`, `finalization_timeout`, the `lease_call_timeout` row, or `request_timeout` for `max_session_duration` or a file bound) shall require that phase's own unclipped deadline to have expired; when two unclipped deadlines fall due at the same instant the phase deadline shall win; and an abnormal cause already selected shall be kept, whereas a provisional normal or shutdown finalization is not a selected cause and does not block a later deadline.
- [ ] **ING-ERR-015**: When a streaming surface is refused before configuration by the ingress cap, engine capacity or draining, it shall answer `busy` (`RESOURCE_EXHAUSTED`) or `service_unavailable` (`UNAVAILABLE`) and, on the Realtime adapter, send `error` and close 1013.
- [ ] **ING-ERR-016**: When the first message is wrong or a later `streaming_config` arrives, the surface shall answer `protocol_order` (`FAILED_PRECONDITION`) and, on the Realtime adapter, send `error` and close 1008.
- [ ] **ING-ERR-017**: When configuration plus `open` exceeds its bound, the surface shall answer `configuration_timeout` (`DEADLINE_EXCEEDED`) and, on the Realtime adapter, send `error` and close 1011.
- [ ] **ING-ERR-018**: When the first-audio bound, the idle bound or the engine's `expired` ends a stream, the surface shall answer `idle_timeout` (`ABORTED`) and, on the Realtime adapter, send `error` and close 1011.
- [ ] **ING-ERR-019**: When `max_session_duration` expires, the surface shall answer `request_timeout` (`DEADLINE_EXCEEDED`) and, on the Realtime adapter, send `error` and close 1011.
- [ ] **ING-ERR-020**: When a `feed` or `update_locale` call exceeds `lease_call_timeout`, the surface shall answer `service_unavailable` (`UNAVAILABLE`) and, on the Realtime adapter, send `error` and close 1011.
- [ ] **ING-ERR-048**: When the finalization bound of a client-selected finalization expires, including one the shutdown trigger finds running (ING-LIFE-055), the surface shall answer `finalization_timeout` (`DEADLINE_EXCEEDED`) and, on the Realtime adapter, send `error` and close 1011.
- [ ] **ING-ERR-022**: When audio cannot be decoded, the surface shall answer `invalid_audio` (`INVALID_ARGUMENT`) and, on the Realtime adapter, send `conversation.item.input_audio_transcription.failed` and close 1008.
- [ ] **ING-ERR-023**: Unless a primary cause is already selected (ING-ERR-005), when `flush` fails, an unexpected failure occurs, `finish` fails, a cleanup bound expires on the normal path, or `release` fails for a reason other than `engine_dead`, the surface shall answer `internal` (`INTERNAL`) and, on the Realtime adapter, send `conversation.item.input_audio_transcription.failed` and close 1011, emitting no final.
- [ ] **ING-ERR-024**: Unless a primary cause is already selected (ING-ERR-005), when any lease call fails with reason `engine_dead`, including `release`, the surface shall answer `service_unavailable` (`UNAVAILABLE`) and, on the Realtime adapter, send `conversation.item.input_audio_transcription.failed` and close 1011.
- [ ] **ING-ERR-058**: When the receive observer of ING-ERR-057 fails a session with `session_terminal`, the Realtime adapter shall send `error` with `session_terminal` and close 1008; on gRPC the half-close ends the request stream, so no client message follows it, the observer sees only cancellation, and the `FAILED_PRECONDITION` projection of `session_terminal` is not reached.
- [ ] **ING-ERR-026**: When a Realtime message or event exceeds a size bound, the adapter shall answer `request_too_large` and close 1009.
- [ ] **ING-ERR-027**: When a shutdown finalization succeeds, gRPC shall end with `OK` after the final and the Realtime adapter shall send `completed` and close 1001.
- [ ] **ING-ERR-059**: When an owner in provisional shutdown mode (ING-LIFE-053) meets a failure or the expiry of a lease-call, finalization or cleanup deadline after it observed the trigger, including during the settlement of an outstanding call, or when `D` arrives before its shutdown finalization completes, and no abnormal cause was selected before the owner observed the trigger, the stream shall end with `service_unavailable` (`UNAVAILABLE`) and, on the Realtime adapter, `error` and close 1012, in place of the row ING-ERR-020, ING-ERR-023 or ING-ERR-024 would otherwise assign; and when `D` arrives before a client-selected finalization the trigger found running completes (ING-LIFE-055), the same row shall apply.

## Seam reasons and exceptions (ERR)

- [ ] **ING-ERR-008**: For a stream owner, the catalog shall map each `SessionRefused` reason on its own: `locale` to `unknown_locale`, `cadence` to `internal`, `capacity` and `active_limit` to `busy` with `authority: provider`, `engine_paused` to `service_unavailable`, and `request_id_in_use` to `internal`.
- [ ] **ING-ERR-013**: For a stream owner, the catalog shall map each `SessionFailed` reason on its own: `expired` to `idle_timeout`, `engine_dead` to `service_unavailable`, `rejected_input`, `abnormal_end` and `state` to `internal`, and `input_capacity` and `output_capacity` to `buffer_overflow` naming the layer.
- [ ] **ING-ERR-014**: For a stream owner, a `SessionFailed` with reason `cancelled` shall project the owner's selected cause, and `internal` when the frontend selected none.
- [ ] **ING-ERR-010**: On a streaming surface, an exception from a factory or lease call without `session_error`, or with a reason the frontend does not know, shall project `internal`, and a failure with reason `engine_dead` shall also escalate (ING-EP-017).
- [ ] **ING-ERR-035**: Unless a primary cause is already selected (ING-ERR-005), a lease `release` failure whose reason is `engine_dead` shall project `service_unavailable` and any other lease `release` failure shall project `internal`.

## File route and `Recognize` (ERR)

- [ ] **ING-ERR-009**: The file route's own errors (400 guard and field refusals, 400 `malformed_request`, 408 and 504 `request_timeout`, 413 `request_too_large`, 501 `unsupported_capability`, 503 `service_unavailable` or `busy`) shall use core's HTTP error shape `{"error": {"message": "<code>: <detail>", "type", "param", "code"}}`, and core's own errors shall pass through unchanged.
- [ ] **ING-ERR-052**: When core's service raises a `VLLMValidationError` for `Recognize`, the frontend shall project `request_too_large` (`RESOURCE_EXHAUSTED`) for a size limit and `invalid_config_field` naming its parameter (`INVALID_ARGUMENT`) otherwise, identifying a size limit by core's own published parameter names and message texts, pinned by a frontend test that runs against core's code.
- [ ] **ING-ERR-053**: When core's service raises a decoder `ValueError` for `Recognize`, the frontend shall project `request_too_large` for an exceeded duration or decode-size limit and `invalid_audio` for an invalid or unsupported file, identifying each case by core's own published message texts, pinned by a frontend test that runs against core's code.
- [ ] **ING-ERR-054**: When core's service raises the model's token-budget `ValueError` for `Recognize`, the frontend shall project `request_too_large` (`RESOURCE_EXHAUSTED`), identifying the refusal by the fixed prefix `file exceeds max_model_len: ` with which the model plugin's FILE-BUD-003 begins the message.
- [ ] **ING-ERR-039**: When core's service raises any other `ValueError` for `Recognize`, including one the frontend cannot match, the frontend shall project `invalid_config_field` (`INVALID_ARGUMENT`) and not `internal`.
- [ ] **ING-ERR-040**: When core's service raises an engine-dead error for `Recognize`, the frontend shall project `service_unavailable` (`UNAVAILABLE`), and for any other exception `internal` (`INTERNAL`).
- [ ] **ING-ERR-041**: A returned `ErrorResponse` from core's service shall be projected for `Recognize` by its HTTP status: 400 or 422 to `invalid_config_field` naming the error's `param` (or `audio`), 413 to `request_too_large`, 501 to `unsupported_capability`, 503 to `service_unavailable`, and other 5xx to `internal`.
