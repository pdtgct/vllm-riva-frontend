# Error catalog specs

Design: [errors-design.md](errors-design.md). Prefix `ING`, facet ERR.

## Catalog and projection (ERR)

- [ ] **ING-ERR-060**: Every error the frontend surfaces on a compatibility dialect shall carry a stable code string from the frontend's error catalog and use that dialect's catalog projection (on gRPC the code leading the status details; on the Realtime WebSocket `conversation.item.input_audio_transcription.failed` for transcription failures and `error` for protocol or session failures), and no failure, rejection or deviation shall be silent; only the refusals and errors of ING-ERR-061 shall carry no catalog code.
- [ ] **ING-ERR-061**: These refusals and errors shall carry no catalog code and shall answer as stated: an HTTP request under `/plugins/riva/` while authentication initialization is unresolved, with 503 and the body `{"error": "Service Unavailable"}` (ING-EP-088); a WebSocket handshake under `/plugins/riva/` while authentication initialization is unresolved, refused before accept with 503 and that body through the ASGI WebSocket denial-response extension, or otherwise with a close before accept (HTTP 403) (ING-EP-088); an HTTP request under `/plugins/riva/` refused by authentication, with core's 401 `{"error": "Unauthorized"}` (ING-EP-084); a WebSocket handshake under `/plugins/riva/` refused by authentication, before accept (ING-EP-087); a connection to the Realtime WebSocket route whose query is not exactly `intent=transcription`, with HTTP 403 before accept and no body (ING-NIMWS-027); an HTTP request for an unknown path under `/plugins/riva/` after authentication, with the router's 404; a WebSocket handshake for a path under `/plugins/riva/` with no WebSocket route after authentication, closed before accept (HTTP 403); a gRPC message above the framework cap, with gRPC's native `RESOURCE_EXHAUSTED` framing error (ING-GRPC-034); the status that the listener stop's termination (grace expiry of ING-EP-074 or forced stop of ING-EP-093) gives an RPC whose own status has not been sent, as the gRPC framework sets it (ING-ERR-062); and core's own errors on the frontend's file route `POST /plugins/riva/v1/audio/transcriptions`, in core's shape unchanged (ING-ERR-009); this spec governs only the wire format of these answers, and the ownership of their sends follows ING-EP-084 and ING-EP-095.
- [ ] **ING-ERR-064**: Every gRPC error the servicer raises shall be raised through `context.abort` with status details of the form `<code>: <detail> (fields: <names>)`; a gRPC error the servicer does not raise (ING-ERR-061), such as the framework's native rejection of a message above `grpc_receive_max_bytes` (ING-GRPC-034), is outside this rule.
- [x] **ING-ERR-051**: A Realtime `error` event shall carry the code and the field names, and `authority` for `busy`, and where the catalog requires a close the adapter shall send every pending event before closing while the transport accepts each send within the send bound of ING-LIFE-061 (a terminal `error` event and close due after the bound, including the shutdown abort row once its bound has passed after the plugin's cancellation of the owner, get the one attempt ING-LIFE-061 allows; a terminal `error` event or close interrupted by that cancellation ends the stream with no further send), and once a send exceeds that bound shall abandon the connection with no further send, including the close frame.
- [x] **ING-ERR-043**: `busy`, `admission_wait_timeout`, `idle_timeout` and `finalization_timeout` shall be distinct catalog codes, no surface shall conflate capacity or load shedding, a bounded admission wait, inactivity, and accepted finalization that reached its bound, and `admission_wait_timeout` shall be reserved and emitted by no surface.
- [x] **ING-ERR-003**: Every rejection of a config field, format or capability shall name the offending field or fields in the error payload.
- [x] **ING-ERR-057**: After a streaming surface accepts client-selected finalization (`input_audio_buffer.done` on the Realtime adapter, the half-close on gRPC), the owner shall keep reading the transport with a receive observer, bounded by the finalization bound and holding at most one received message, from acceptance (including during the final-tail `feed` and `flush`, an exception to ING-CORE-021's no-read rule) until the final's send begins or the owner observes the shutdown trigger, which cancels the observer; on the Realtime adapter a malformed or unknown envelope it sees shall keep `invalid_event` and close 1008 (ING-NIMWS-023), a message above the receive cap shall keep `request_too_large` and close 1009, and every other client message (`input_audio_buffer.append`, `clear`, `commit` or `done`, or `transcription_session.update`) shall fail the session with `session_terminal`; each of these three dispositions shall run under the state-aware cleanup of ING-LIFE-026, suppress the final whose send has not begun and make no lease call when it fires after `release`; once the final's send has begun the final shall be irrevocable and the owner shall read no further traffic; and no surface shall inherit core's silent second-commit behaviour.
- [x] **ING-ERR-005**: An unexpected engine, session-factory, plugin, transport or terminal-cleanup failure with no more specific primary catalog error shall project `internal`, and a cleanup failure shall never replace an already-selected cancellation, deadline, validation, transport or engine error.
- [x] **ING-ERR-046**: `service_unavailable`, `configuration_timeout`, `request_timeout`, `malformed_request` and `request_too_large` shall be distinct catalog codes meaning respectively that the plugin is starting, draining or not ready; that initial configuration plus `open` exceeded `preconfiguration_timeout`; that a streaming session exceeded `max_session_duration`, a file request to `Recognize` or the frontend's file route exceeded its body-read, execution or response-send bound, or a gRPC absolute deadline won under the deadline precedence rule (ING-ERR-056); that the multipart content type, boundary, structure, required file or framing of a request to the frontend's file route is invalid; and that a bounded unary, audio-duration, WebSocket-envelope or frontend file-route body resource exceeded its limit.
- [x] **ING-ERR-031**: The catalog shall project the 20 codes to gRPC statuses `service_unavailable` `UNAVAILABLE`, `busy` and `request_too_large` and `buffer_overflow` `RESOURCE_EXHAUSTED`, `idle_timeout` `ABORTED`, `finalization_timeout` and `configuration_timeout` and `request_timeout` `DEADLINE_EXCEEDED`, `malformed_request` and `invalid_event` and `invalid_config_field` and `unknown_locale` and `unsupported_format` and `invalid_audio` `INVALID_ARGUMENT`, `session_terminal` and `protocol_order` `FAILED_PRECONDITION`, `unsupported_capability` `UNIMPLEMENTED`, `internal` `INTERNAL`, `config_change_rejected` `OK` (never raised as an abort) and `admission_wait_timeout` `DEADLINE_EXCEEDED`.
- [x] **ING-ERR-055**: The frontend's file route shall project catalog codes to HTTP statuses `malformed_request` 400, `invalid_config_field` 400, `unknown_locale` 400, `request_too_large` 413, `request_timeout` 408 for a body-read timeout and 504 for a core-execution timeout before response headers are sent (after them the event stream is terminated, ING-FILE-035), `service_unavailable` 503, `busy` 503, `unsupported_capability` 501 (files disabled only) and `internal` 500, and a response-send timeout shall end delivery with no further send.
- [x] **ING-ERR-033**: The Realtime adapter shall project `invalid_config_field`, `unsupported_capability`, `unknown_locale` and `config_change_rejected` as an `error` that leaves the session continuing when no state changed.
- [x] **ING-ERR-034**: A format or configuration rejection before the first Realtime configuration completes shall not close the connection, so that the client can retry with a corrected `transcription_session.update`.

## Phase-specific mapping (ERR)

- [x] **ING-ERR-011**: The phase table of the errors design shall govern the code, gRPC status, Realtime event and close of every streaming-session phase, and where another leaf states one of those values the phase table shall govern on any conflict.
- [x] **ING-ERR-056**: Every deadline an owner holds (a phase bound, the gRPC RPC's absolute deadline, the drain deadline `D` once a running `drain` call has announced it, ING-EP-082) shall keep its original absolute value and its identity, and clipping (ING-LIFE-062) shall shorten only the wait (a stream owner's terminal cleanup bound that begins during a `drain` call's graceful work is not a clipped deadline but is set to the time remaining to `D`, ING-LIFE-059), so that a wait that ends because it reached `D` shall expire as `D` and not as its phase; the earliest expired deadline shall win; a phase's code (`configuration_timeout`, `idle_timeout`, `finalization_timeout`, the `lease_call_timeout` row, or `request_timeout` for `max_session_duration` or a file bound) shall require that phase's own unclipped deadline to have expired; when two unclipped deadlines fall due at the same instant the phase deadline shall win; and an abnormal cause already selected shall be kept, whereas a provisional normal or shutdown finalization is not a selected cause and does not block a later deadline.
- [x] **ING-ERR-015**: When a streaming surface is refused before admission by the ingress cap or a draining plugin, or its owner is refused by engine capacity when `open` raises, the surface shall answer `busy` (`RESOURCE_EXHAUSTED`) or `service_unavailable` (`UNAVAILABLE`) and, on the Realtime adapter, send `error` and close 1013.
- [ ] **ING-ERR-063**: When `open` raises `SessionRefused` (ING-ERR-008) with a reason other than `capacity` or `active_limit` (ING-ERR-015), the surface shall answer by reason: `engine_paused` with `service_unavailable` (`UNAVAILABLE`) and, on the Realtime adapter, `error` and close 1013; `cadence` or `request_id_in_use` with `internal` (`INTERNAL`) and, on the Realtime adapter, `error` and close 1011; and `locale` with `unknown_locale` (`INVALID_ARGUMENT`) and, on the Realtime adapter, an `error` with no close, the session staying unconfigured and accepting a corrected `transcription_session.update` within the original `preconfiguration_timeout` (ING-CORE-021, ING-LIFE-022); and for every such refusal except `locale` on the Realtime adapter the owner shall end without a lease.
- [x] **ING-ERR-016**: When the first message is wrong or a later `streaming_config` arrives, the surface shall answer `protocol_order` (`FAILED_PRECONDITION`) and, on the Realtime adapter, send `error` and close 1008.
- [x] **ING-ERR-017**: When configuration plus `open` exceeds its bound, the surface shall answer `configuration_timeout` (`DEADLINE_EXCEEDED`) and, on the Realtime adapter, send `error` and close 1011.
- [x] **ING-ERR-018**: When the first-audio bound, the idle bound or the engine's `expired` ends a stream, the surface shall answer `idle_timeout` (`ABORTED`) and, on the Realtime adapter, send `error` and close 1011.
- [x] **ING-ERR-019**: When `max_session_duration` expires, the surface shall answer `request_timeout` (`DEADLINE_EXCEEDED`) and, on the Realtime adapter, send `error` and close 1011.
- [x] **ING-ERR-020**: When a `feed` or `update_locale` call exceeds `lease_call_timeout`, the surface shall answer `service_unavailable` (`UNAVAILABLE`) and, on the Realtime adapter, send `error` and close 1011.
- [x] **ING-ERR-048**: When the finalization bound of a client-selected finalization expires, including one the shutdown trigger finds running (ING-LIFE-055), the surface shall answer `finalization_timeout` (`DEADLINE_EXCEEDED`) and, on the Realtime adapter, send `error` and close 1011.
- [x] **ING-ERR-022**: When audio cannot be decoded, the surface shall answer `invalid_audio` (`INVALID_ARGUMENT`) and, on the Realtime adapter, send `conversation.item.input_audio_transcription.failed` and close 1008.
- [x] **ING-ERR-023**: Unless a primary cause is already selected (ING-ERR-005), when `flush` fails, an unexpected failure occurs, `finish` fails, a cleanup bound expires on the normal path, or `release` fails for a reason other than `engine_dead`, the surface shall answer `internal` (`INTERNAL`) and, on the Realtime adapter, send `conversation.item.input_audio_transcription.failed` and close 1011, emitting no final.
- [x] **ING-ERR-024**: Unless a primary cause is already selected (ING-ERR-005), when any lease call fails with reason `engine_dead`, including `release`, the surface shall answer `service_unavailable` (`UNAVAILABLE`) and, on the Realtime adapter, send `conversation.item.input_audio_transcription.failed` and close 1011.
- [x] **ING-ERR-058**: When the receive observer of ING-ERR-057 fails a session with `session_terminal`, the Realtime adapter shall send `error` with `session_terminal` and close 1008; on gRPC the half-close ends the request stream, so no client message follows it, the observer sees only cancellation, and the `FAILED_PRECONDITION` projection of `session_terminal` is not reached.
- [x] **ING-ERR-026**: When a Realtime message or event exceeds a size bound, the adapter shall answer `request_too_large` and close 1009.
- [x] **ING-ERR-027**: When a shutdown finalization succeeds, gRPC shall end with `OK` after the final and the Realtime adapter shall send `completed` and close 1001.
- [ ] **ING-ERR-062**: When an owner in provisional shutdown mode (ING-LIFE-053) meets a failure or the expiry of a lease-call, finalization or cleanup deadline after it observed the trigger, including during the settlement of an outstanding call, or when `D` arrives before its shutdown finalization completes, and no abnormal cause was selected before the owner observed the trigger, the owner shall select the shutdown abort row, `service_unavailable` (`UNAVAILABLE`) and, on the Realtime adapter, `error` and close 1012, in place of the row ING-ERR-020, ING-ERR-023 or ING-ERR-024 would otherwise assign, and when `D` arrives before a client-selected finalization the trigger found running completes (ING-LIFE-055), the same row shall apply; the row's terminal status shall be sent under the send rules of ING-LIFE-061, and on gRPC, once the plugin has begun stopping the gRPC listener, its `UNAVAILABLE` status shall reach the client only when that send completes before the listener stop's termination (grace expiry of ING-EP-074 or forced stop of ING-EP-093), the status of that termination carrying no catalog code (ING-ERR-061).

## Seam reasons and exceptions (ERR)

- [x] **ING-ERR-008**: For a stream owner, the catalog shall map each `SessionRefused` reason on its own: `locale` to `unknown_locale`, `cadence` to `internal`, `capacity` and `active_limit` to `busy` with `authority: provider`, `engine_paused` to `service_unavailable`, and `request_id_in_use` to `internal`.
- [x] **ING-ERR-013**: For a stream owner, the catalog shall map each `SessionFailed` reason on its own: `expired` to `idle_timeout`, `engine_dead` to `service_unavailable`, `rejected_input`, `abnormal_end` and `state` to `internal`, and `input_capacity` and `output_capacity` to `buffer_overflow` naming the layer.
- [x] **ING-ERR-014**: For a stream owner, a `SessionFailed` with reason `cancelled` shall project the owner's selected cause, and `internal` when the frontend selected none.
- [x] **ING-ERR-010**: On a streaming surface, an exception from a factory or lease call without `session_error`, or with a reason the frontend does not know, shall project `internal`, and a failure with reason `engine_dead` shall also escalate (ING-EP-111).
- [x] **ING-ERR-035**: Unless a primary cause is already selected (ING-ERR-005), a lease `release` failure whose reason is `engine_dead` shall project `service_unavailable` and any other lease `release` failure shall project `internal`.

## File route and `Recognize` (ERR)

- [x] **ING-ERR-009**: The errors that the frontend's file route raises itself (400 guard and field refusals, 400 `malformed_request`, 408 and 504 `request_timeout`, 413 `request_too_large`, 501 `unsupported_capability`, 503 `service_unavailable` or `busy`) shall use core's HTTP error shape `{"error": {"message": "<code>: <detail>", "type", "param", "code"}}`, and core's own errors on that route shall pass through unchanged.
- [x] **ING-ERR-052**: When core's service raises a `VLLMValidationError` for `Recognize`, the frontend shall project `request_too_large` (`RESOURCE_EXHAUSTED`) for a size limit and `invalid_config_field` naming its parameter (`INVALID_ARGUMENT`) otherwise, identifying a size limit by core's own published parameter names and message texts, pinned by a frontend test that runs against core's code.
- [x] **ING-ERR-053**: When core's service raises a decoder `ValueError` for `Recognize`, the frontend shall project `request_too_large` for an exceeded duration or decode-size limit and `invalid_audio` for an invalid or unsupported file, identifying each case by core's own published message texts, pinned by a frontend test that runs against core's code.
- [x] **ING-ERR-039**: When core's service raises any other `ValueError` for `Recognize`, including one the frontend cannot match, the frontend shall project `invalid_config_field` (`INVALID_ARGUMENT`) and not `internal`.
- [x] **ING-ERR-040**: When core's service raises an engine-dead error for `Recognize`, the frontend shall project `service_unavailable` (`UNAVAILABLE`), and for any other exception `internal` (`INTERNAL`).
- [x] **ING-ERR-041**: A returned `ErrorResponse` from core's service shall be projected for `Recognize` by its HTTP status: 400 or 422 to `invalid_config_field` naming the error's `param` (or `audio`), 413 to `request_too_large`, 501 to `unsupported_capability`, 503 to `service_unavailable`, and other 5xx to `internal`.
