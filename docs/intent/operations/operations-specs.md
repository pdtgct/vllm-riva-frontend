# Operations specs

Design: [operations-design.md](operations-design.md). Prefix `ING`, facets SHIM, CLI.

## Operational routes (SHIM)

- [ ] **ING-SHIM-023**: The frontend's route set shall be exactly the four operational routes (ING-SHIM-018), the Realtime bootstrap `POST /plugins/riva/v1/realtime/transcription_sessions`, the Realtime WebSocket route `/plugins/riva/v1/realtime` and, when `attach_router` adds it (ING-FILE-075), the frontend's file route `POST /plugins/riva/v1/audio/transcriptions`, every route in it new and under `/plugins/riva/v1/`.
- [ ] **ING-SHIM-018**: The plugin shall serve `GET /plugins/riva/v1/health/ready`, `GET /plugins/riva/v1/health/live`, `GET /plugins/riva/v1/version` and `GET /plugins/riva/v1/metadata` on the HTTP listener with NIM-shaped response and error bodies, keeping the NIM `v1/...` suffix under the plugin's prefix so that NIM tooling given the base URL `host:port/plugins/riva` reaches them, and the readiness body shall be a JSON object whose `status` is `ready` when the plugin's `ready(state)` predicate (ING-EP-065) is true and `not_ready` when it is false (ING-SHIM-009); every requirement on the frontend's readiness, liveness, version or metadata route binds only that route under `/plugins/riva/v1/`, never core's `/ready`, `/health` or `/version`.
- [ ] **ING-SHIM-024**: The frontend's readiness route `GET /plugins/riva/v1/health/ready` shall report the plugin's `ready(state)` predicate alone, the same predicate core's `/ready` aggregates with engine health and `state.draining`, and the plugin shall leave core's `/health` reporting engine health only, without reading plugin readiness.
- [x] **ING-SHIM-009**: The frontend's readiness route shall answer 200 with `{"object": "health.response", "message": "ready", "status": "ready"}` when ready and 503 with `message` `not ready` and `status` `not_ready` otherwise.
- [x] **ING-SHIM-010**: The frontend's liveness route shall answer 200 with `{"object": "health.response", "message": "live", "status": "live"}` whenever the HTTP server serves it to a request that passes authentication (ING-EP-084), and shall define no `not_live` response.
- [x] **ING-SHIM-011**: The frontend's version route shall answer 200 with `release` equal to the frontend distribution version and `api` equal to `v1`.
- [ ] **ING-SHIM-025**: The `version` field of `GET /plugins/riva/v1/metadata` shall equal the `release` that `GET /plugins/riva/v1/version` reports.
- [ ] **ING-SHIM-027**: Every frontend surface that publishes deployment provenance (`GET /plugins/riva/v1/metadata` and the Riva Realtime session) shall take it from the one deployment provenance object that `init_state` builds (ING-SHIM-012), so that every surface publishes the same identifiers.
- [ ] **ING-SHIM-019**: `GET /plugins/riva/v1/metadata` shall report only identifiers of this deployment (its image identifier, release pin identifier, resolved served-model identity and precision identifier) and shall never reproduce a Speech NIM model-registry identity, a registry-scheme provenance reference or a NIM profile hash.
- [x] **ING-SHIM-012**: The frontend's metadata `provenance` object shall be built from exactly the four typed fields image, pin, precision policy and resampler, `modelInfo` shall hold one entry whose `shortName` is the served-model identity, and `repository_override`, `assetInfo` and `licenseInfo` shall be empty.
- [ ] **ING-SHIM-021**: Under `--api-key` or `VLLM_API_KEY`, every frontend HTTP and WebSocket route (the four operational routes, the Realtime bootstrap, the Realtime WebSocket route and the frontend's file route) shall require the bearer token as ING-EP-084 applies it, an HTTP request without it receiving core's 401 and a WebSocket handshake without it being refused before accept (ING-EP-087), while `OPTIONS` requests and core's `/health` and `/ready` need no token, core's `/v1/...` routes keep core's own check, and the gRPC listener stays outside `--api-key` (ING-EP-090).
- [ ] **ING-SHIM-022**: The frontend's Realtime WebSocket route `/plugins/riva/v1/realtime` shall run inside core's WebSocket metrics middleware, so that core's realtime connection gauges count each open Riva Realtime session on `/plugins/riva/v1/realtime` and each admission refusal the route accepts before closing (ING-NIMWS-028), and do not count a connection refused for its query (ING-NIMWS-027), which is never accepted.
- [ ] **ING-SHIM-026**: A check shall parse the repository's deployment guide, `docs/deployment.md`, and fail unless it states that a liveness probe that cannot supply the bearer token probes core's `/health`, and that under `--api-key` tooling that probes the frontend's operational routes under `/plugins/riva/v1/` supplies the token.

## Coexistence (SHIM)

- [ ] **ING-SHIM-020**: The plugin shall leave core's `/health`, `/ready`, `/v1/models`, `/version`, `/v1/realtime`, `/v1/audio/transcriptions` and metrics endpoints authoritative, replacing, shadowing or reinterpreting none of them, and shall add no route outside `/plugins/riva/` (so no `GET /v1/health` or `GET /v1/metrics`); the checks that keep the frontend's route set and core's routes apart are ING-EP-091, ING-EP-070 and ING-EP-092.

## Evaluation (CLI)

- [ ] **ING-CLI-005**: The Riva gRPC and Riva Realtime WebSocket surfaces shall be driven in evaluation by the canonical `nvidia-riva/python-clients` tools (the gRPC tools given the server's gRPC `host:port`, the Realtime client given `--server host:port/plugins/riva` with its default endpoint and query, and `GetRivaSpeechRecognitionConfig` exercised by the stock model-listing script), the frontend's file route `POST /plugins/riva/v1/audio/transcriptions` by an OpenAI-style multipart transcription request, and the frontend shall implement no bespoke Riva-family client.
- [ ] **ING-CLI-006**: The stock Riva Realtime client shall be evaluated against a server with API-key authentication disabled (neither `--api-key` nor `VLLM_API_KEY` set), and the bearer-token behaviour of `/plugins/riva/` shall be verified by CPU tests that send requests with and without the token.
